For **@aifinpay/mcp 2.12.1**. Use the server's `tools/list` for exact input
schemas in your installed version.

| Tool | Purpose |
|---|---|
| `payment_setup_status` | Read-only checklist: wallet, payments enabled, limits, balance, `funding` amount and one `next_step` |
| `payable_fetch` | Pay for and fetch an AIFP-1 resource (Polygon by default, or the owner-selected served network); always listed; returns the setup checklist while the wallet is ephemeral, unfunded or payments are switched off, and without an origin allowlist pays only a merchant that verified the site being fetched |
| `agent_address` | Read the selected wallet's public addresses |
| `agent_claim_self` | Link the agent to its owner's dashboard with a one-time URL from My Agents |
| `agent_reload` | Reload wallet files in the current connection; reports `payments_enabled` and, when payments are off, that env changes need a server restart |
| `agent_quota` | Inspect hosted-meter quota; self-hosted consumption is tracked by the merchant |
| `agent_history` | Read indexed transactions or retained batch history |
| `agent_passport_resolve` | Resolve a public Agent Passport |
| `settlement_routes` | Inspect routes: AIFP-1 v1.4 first with live state, legacy v1.3 separately |
| `settlement_invoice` | Prepare a non-signing settlement invoice |
| `settlement_solana` | Inspect Solana settlement instructions |
| `settlement_casper` | Inspect Casper settlement instructions |
| `deployment_info` | Read deployment metadata |
| `dev_payment_quote` | Request a dev quote; only registered in dev mode |

`payable_fetch` is the only tool that moves funds, and only within the owner's
configured limits and origins. `agent_claim_self` signs only an AiFinPay claim
challenge for the agent's own address. `agent_reload` changes the in-process
wallet selection; it does not transfer funds.

The server also exposes the Markdown resource `aifinpay://skill`. Read it for
wallet selection and the current workflow.

## Tools not registered

`agent_call`, `agent_quote`, `pay_with_split` and `quote_split` are not
registered. Do not instruct an agent to call them or to replace a missing
payment tool with improvised transaction signing. If `payable_fetch` answers
with a checklist instead of paying, follow its `next_step`: payments are not yet
enabled in this server's configuration, or the server has not been restarted
since they were.
